2 · 模型实际看见什么

两通道：tools = 可调用说明书；文本 = 薄目录广告。Deferred = 目录可见，说明书先不发。

通道 A · tools 数组（可调用）

只有这些能被 function call

shell
apply_patch
update_plan
tool_search ← 发现入口

没有 jira.create_issue

没有 slack.post_message

没有 20×N 份 schema

体积：核心工具 + 1 个 search ≈ 几千 tokens

模型现在：能改代码，不能直接调 Jira API

通道 B · 文本广告（world-state / description）

整表大约一两百 tokens，不是 20 份 API 文档

## Deferred tool namespaces - github: Repos, PRs, issues, checks - gitlab: MRs and pipelines - jira: Issues, sprints, transitions ← 有这行才「知道有 Jira」 - linear: Product issues and cycles - slack: Channels and messages - notion / confluence / google_drive … - sentry / datadog / pagerduty … - stripe / snowflake / bigquery … - figma / playwright / browserbase / postgres / filesystem
tool_search 自己的 description
Some tools were not provided upfront — use tool_search to discover them.

模型拼装：薄目录 + search 入口 + 用户意图 · 不是两眼一抹黑，也不是全量 schema

3 · 用户要建 Jira

意图对上广告里的 jira 桶 → 本轮只能调 tool_search，还不能直接 create_issue。

用户消息

把 login 超时这个 bug 建一张 Jira，priority High，打上 backend 标签。
模型本轮推理（示意）
1. 任务要写 Jira issue 2. tools 数组：无 jira.* 可调 3. 广告目录：有 “jira: Issues…” 4. 结论：先 tool_search，不能瞎编参数 5. 改代码工具这轮用不上 → 不调 shell
若广告里没有 jira？

正确：告诉用户未连接，或空搜一次后停

错误：幻想参数硬调（runtime 也会拒未注册工具）

本轮 tools 仍只有这些

shell
apply_patch
tool_search ← 将调用
为什么不直接调 jira？

schema 还没进 tools 数组。协议要求：先看见 definition，再 function call。

「下一拍」= 同一次 agent loop 的下一次 model completion，不是用户再发一句。

业务含义

主路径改代码的多数 turn：不付 Jira schema 税

偶发要连 Jira：愿意多 1 拍 discovery

整段时序账本

  • T0 装 20 MCP · Deferred
  • T1 广告薄目录 + Direct 工具
  • T2 用户：建 Jira
  • T3 tool_search（上一拍）
  • T4 BM25 → schema 回写
  • T5 本拍 call create_issue
  • T6 MCP 执行 · 回 issue key

少付：~20 MCP 全 schema × 每轮

多付：1 次 search 模型步

主路径改代码 turn：连 search 都不必走
